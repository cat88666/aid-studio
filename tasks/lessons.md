- 用户提到沿用服务器时，先核对 ArcReel 和 llm-modes-gateway 的现役部署记录，再用 SSH 别名只读检查现场。仅询问记录无法确定的事项。
- 用户要求使用公网 IP 时，以公网设备验证 HTTPS、页面和 API 为验收条件；SSH 转发只用于受限管理入口。
- 页面和列表接口成功后，还要抽查每类真实媒体的响应类型并实际解码；HTTP 200 可能包着业务 404。验收要覆盖登录后的导航、风格预览、素材和试听。
- 用户报告可自行复现的故障时，优先复用现有账号和线上证据，横向排查相关页面，不把收集截图或路径作为用户的前置工作。
- 用户要求公网管理后台时，将管理页面和 API 一起挂到现有 HTTPS Nginx 入口，用公网登录验证后交付可点击地址。
- 长期同步作者的 fork，先从可追溯提交复制 C 端；品牌、页面及样式改在独立副本，原版目录留给上游同步。指定一比一对照时先取样，再确认视觉方案。
- 定制前端与作者原版需要并行上线时，先逐个核对源码、产物、URL 和 API 前缀。此项目三个正式入口是根路径 creator、/web/ 原版和 /admin/ 后台。
- 品牌面向全球时，先明确英文品牌和海外用户的首次体验；同时验收英文浏览器、中文浏览器及手动切换。
- 首页上的浏览、帮助和个人账单入口优先就地展示；验收要从用户正在浏览的语言页实际点击，核对地址、滚动位置与视觉连续性。
- 对照复刻时，验收用户实际停留的语言和锚点；用相同视口留存生产改动前后图，分别报告布局差异与功能验证。
- 用户给出参考站导航或查询参数时，先逐项核对同一应用状态的入口、URL 与页面结构；营销首页截图不能作为创作者工作台的验收依据。
- 首页复刻要核对当前真实参考页的完整模块、卡片密度、导航与交互。局部表单和几张样片通过功能测试，不能代替完整首页的对照验收。
- 用户要求首页丰富时，视频数量、题材和画面差异必须单独验收；补齐页面模块不等于素材丰富，不能用同一视频不同封面凑数。
- 浅色主题覆盖旧暗色组件时，文字、背景、边框和图标必须成套检查；验收必须覆盖未悬停默认状态，不能只在鼠标停留状态判断可读性。
- 全页样式巡检需打开portal弹窗和下拉，验证实际文字子节点与背景；AntD版本变化后用浏览器确认DOM，防止父按钮颜色误报和旧class覆盖失效。
- 注册体验要先核对真正可用的身份渠道：方法选择、验证码注册和已有账号登录分别设计；参考海外产品时核对Google真实接入条件，不能用装饰按钮或未配置的发送服务冒充可注册。

- 共享主机调整根路径、域名或HTTPS入口时，必须逐项保留并验证网关/playground、/v1/、健康检查与媒体公网地址；不能只验证新部署应用。把共存服务探针纳入后续部署验收，避免页面落入其他应用。
